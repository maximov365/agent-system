# Artifact quality loop

Use when a substantial specification, plan, design, research synthesis, or decision document has uncertainty that review can resolve. Follow `AGENTS.md`. The owner may review and revise locally; separate agents are optional and require applicable delegation authorization.

1. Review the artifact against its acceptance criteria, source evidence, project constraints, and intended downstream use.
2. Record concrete defects with their consequence and correction; distinguish blocking issues from preferences.
3. Revise affected areas and recheck findings. Preserve accepted scope and acceptance criteria.
4. Accept when substantive criteria are satisfied and no material unresolved conflict remains. Identify reviewer provenance honestly.

If progress stalls, change the approach, reduce uncertainty, or use another available verification method. Ask the user only for a missing decision/input that prevents progress. An iteration counter or numerical score alone never requires escalation or proves quality. Respect an explicit user-specified time or iteration budget and report unfinished work when it is exhausted.

Optional structured adapters may transport Spec Reviewer findings to Gatekeeper and Reviser using the handoff contract. Those are methods and data formats, not mandatory local role cycles. Code changes still require relevant correctness/security checks; visual artifacts require viewed evidence from `docs/VISUAL_QUALITY.md`.
