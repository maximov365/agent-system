# Optional skills and portable methods

This filename is retained for existing references. Skills are reusable workflows,
not a Claude-only capability. Consult the current host's documentation for its
discovery paths and supported metadata; see `docs/CODEX.md` for Codex.

Use a skill only when it is exposed in the current session and its scope fits the
task. A name in this document, an old plugin catalog or an `agents/*.md` role file
does not establish installation or availability. An explicit request for a missing
skill requires locating it or explaining what is unavailable, not pretending it ran.

Framework methods work without optional plugins. Native skills supplied by this
framework route to the same project contracts and shared references. Do not keep a
second copy of the methodology inside every role or load a catalog for each edit.
One small UI fix needs the relevant method, not every design skill.

Useful optional capabilities include design review, accessibility, measured web
performance, database-specific checks and asset production. Select these against
an actual gap. For example, [Web Quality Skills](https://github.com/addyosmani/web-quality-skills)
can add depth to a web audit; it is not an installed dependency or evidence of a
completed Lighthouse run. Browser, image and device tools may be native to the
host and do not inherently require MCP.

Before adopting an external skill, inspect its current instructions, scripts,
license and installation effects. Preserve project identity, selected model and
authorization. Retain attribution for copied material. Avoid duplicate triggers,
mandatory provider switching, automatic delegation or undocumented hooks.
Keep executable additions opt-in and versioned. Removing an optional skill must
not remove acceptance criteria or make the framework unusable.

Validate skill metadata and references, then exercise representative requests.
Metadata validation does not demonstrate better design or model performance.
Report actual tools, observed evidence and remaining limitations; role names and
self-assigned scores do not establish independent review.
